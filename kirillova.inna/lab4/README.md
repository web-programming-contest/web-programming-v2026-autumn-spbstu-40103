# Лабораторная работа 4

## Задание

Вариант 36. Задача «Пользователи и друзья».

4.1. Создать класс `User` с полями:

- `id` — уникальный идентификатор (число);
- `name` — имя пользователя (строка);
- `friends` — массив id друзей (числа).

Реализовать методы:

- `addFriend(friendId)` — добавить друга;
- `removeFriend(friendId)` — удалить друга;
- геттер `friendCount` — возвращает количество друзей.

4.2. Дан массив пользователей. Реализовать функции:

- группировка пользователей по количеству друзей;
- уникальный список всех друзей;
- список пользователей, у которых есть общий друг с заданным id;
- пользователи, у которых количество друзей больше заданного;
- список пользователей, не имеющих друзей.

4.3. Пользовательский интерфейс:

- список карточек пользователей (имя, ID, список друзей);
- кнопки «Добавить друга», «Удалить друга», «Добавить пользователя», «Удалить
  пользователя»;
- форма создания пользователя (ID, имя) и формы управления друзьями (по ID);
- автоматическое обновление интерфейса при любых изменениях;
- все операции добавления/удаления — асинхронно через `Promise + setTimeout()`;
- сохранение текущего списка пользователей в `localStorage`.

## Реализация

### Модель (`model.js`)

Класс `User` хранит `id`, `name` и собственную копию массива `friends`
(конструктор не сохраняет ссылку на переданный массив, чтобы не мутировать
данные вызывающего кода). Геттер `friendCount` возвращает `friends.length`.
`addFriend` добавляет id только если его ещё нет в списке и он не равен
собственному id пользователя (защита от добавления себя в друзья).
`removeFriend` отфильтровывает переданный id друга.

Именованно экспортируются пять функций работы с коллекцией пользователей, ни
одна из них не изменяет исходный массив:

- `groupUsersByFriendCount(users)` — группирует пользователей в `Map`, где ключ
  — количество друзей, значение — массив пользователей с этим количеством;
- `getUniqueFriends(users)` — собирает id всех друзей всех пользователей в `Set`
  и возвращает как массив без повторов;
- `findUsersWithFriend(users, friendId)` — фильтрует пользователей, в чьём
  списке `friends` есть `friendId`;
- `findUsersAboveFriendCount(users, count)` — фильтрует пользователей с
  `friendCount > count`;
- `findUsersWithoutFriends(users)` — фильтрует пользователей с
  `friendCount === 0`.

### Интерфейс (`index.html`, `main.js`, `styles.css`)

Публичный DOM-контракт:

| Элемент                    | Селектор                          |
| -------------------------- | --------------------------------- |
| Список пользователей       | `[data-testid="entity-list"]`     |
| Форма добавления           | `form[data-testid="entity-form"]` |
| Карточка пользователя      | `[data-testid="entity-card"]`     |
| Кнопка удаления в карточке | `[data-testid="delete-entity"]`   |

Разметка построена с использованием семантических тегов HTML5. Форма создания
пользователя имеет поля `name="id"` и `name="name"`. Каждая карточка
пользователя, созданная из шаблона (`<template id="user-card-template">`),
содержит:

- имя, id и список друзей (или «нет», если друзей нет);
- форму добавления друга по его ID (`data-role="add-friend-form"`) с валидацией
  на существование пользователя и запретом самодобавления;
- форму удаления конкретного друга по его ID (`data-role="remove-friend-form"`)
  с проверкой на наличие указанного ID в списке друзей;
- кнопку удаления пользователя (`data-testid="delete-entity"`).

Все операции изменения состояния (`addUser`, `removeUser`, `addFriend`,
`removeFriend`) обёрнуты в `runAsync`, которая возвращает
`new Promise((resolve) => setTimeout(() => resolve(action()), 300))` — то есть
выполняются асинхронно. Пока промис не разрешился, список карточек не меняется;
перерисовка (`render()`) вызывается только в `.then()`.

Состояние синхронизируется с `localStorage` при каждом изменении (`saveUsers`) и
восстанавливается при загрузке страницы (`loadUsers`) с защитой от поврежденных
данных, так что список сохраняется между перезагрузками и закрытием вкладки.
